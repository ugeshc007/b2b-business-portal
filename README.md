# B2B Business Portal

Production-oriented two-company procurement system for Dealzarabia and Buy2day.

## Portals

- Admin: `/`
- Dealzarabia: `/dealzarabia`
- Buy2day: `/buy2day`

All portals use one database, with records separated by company. This keeps today’s operation simple while allowing future split deployment.

## Local Run

```bash
npm install
npm run db:init
npm run prisma:generate
npm run seed
npm run dev
npm run web
```

Frontend dev URL: `http://127.0.0.1:5321`

API URL: `http://127.0.0.1:4321`

## Production Run

### One-Click Windows Local Setup

Run PowerShell as normal user from the project folder:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup-local-windows.ps1
```

The script will:

- create `.env.production`
- generate a secure `JWT_SECRET`
- install packages
- prepare SQLite database
- seed admin user, Dealzarabia, Buy2day, products, and stock
- build the frontend

Default login:

```text
User: admin@example.com
Password: ChangeMe123!
```

To use your own admin login:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup-local-windows.ps1 -AdminEmail "owner@example.com" -AdminPassword "StrongPasswordHere"
```

To reset the database during setup:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup-local-windows.ps1 -ResetDatabase
```

After setup, start the local production server:

```powershell
npm run start:prod
```

Open:

```text
http://127.0.0.1:4321
```

1. Copy `.env.production.example` to `.env.production`.
2. Set a real HTTPS `APP_ORIGIN`.
3. Set a random `JWT_SECRET` with at least 32 characters.
4. Set a strong `ADMIN_PASSWORD`.
5. Run:

```bash
npm ci
npm run prisma:generate
npm run db:init
npm run build
set NODE_ENV=production
npm run prod:check
npm run start:prod
```

On Linux/macOS use `export NODE_ENV=production` instead of `set`.

## Docker

docker compose up --build -d

Before first Docker run, create `.env.production` from `.env.production.example`.

## Production Notes

- Current database is SQLite, suitable for a first single-server deployment with backups. For multi-user, multi-location, or high-volume operation, migrate to PostgreSQL.
- Gmail is configured as simulation/ready-to-connect. Do not store Gmail passwords. Use Google OAuth or app-password token storage before enabling live sending/reading.
- Gmail production config requires `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`, and `GMAIL_TOKEN_ENCRYPTION_KEY`.
- Invoice PDFs are generated by the backend and stored under `storage/invoices`. The download endpoint is `/api/invoices/:id/pdf`, and invoice email logs store `attachmentPath` for later live Gmail attachment.
- Keep `prisma/*.db` backed up daily if using SQLite.
- Put the app behind HTTPS reverse proxy before internet exposure.
- Rotate the admin password and JWT secret before production.
